# OpenCode: управляемый исполнитель экспериментов

Эта папка содержит **проектную**, а не глобальную настройку OpenCode. OpenCode
здесь не участвует в планировании или финальном ревью: пользователь и Codex
выполняют их вне OpenCode и передают исполнителю лишь утверждённую задачу или
очередь задач. Главные файлы:

| Файл | Назначение |
|---|---|
| `../opencode.json` | безопасные настройки, запрет публикации и доступа к секретам |
| `../AGENTS.md` | общий контур управления, инварианты и формат evidence |
| `agents/executor.md` | primary-исполнитель утверждённых `READY` задач |
| `agents/reviewer-remediator.md` | primary-ревьюер, который исправляет только `REVIEW` задачи с замечанием Control Plane |
| `tasks/WORK_QUEUE.md` | единственный разрешённый источник задач для исполнителя |

## Первый запуск

1. В macOS-приложении OpenCode откройте именно корневую папку репозитория — ту,
   где лежат `opencode.json` и `AGENTS.md`.
2. Откройте новую сессию для этой папки. Агент `executor` должен быть выбран по
   умолчанию; при необходимости выберите его в переключателе агентов приложения.
3. Убедитесь, что в списке проекта присутствуют `.opencode/agents/executor.md` и
   `.opencode/tasks/WORK_QUEUE.md`. Если `executor` не появился, закройте сессию,
   заново откройте проект и проверьте расположение файлов.
4. Не включайте в приложении автоматическое одобрение запросов: оно обходит
   контроль для операций со статусом `ask`.

## Контролируемый сценарий

### 1. Планирование и постановка — вне OpenCode

Мы с пользователем формируем план, границы, критерии приёмки, разрешённые пути,
проверки и условия commit. Затем Codex вносит одну или несколько task cards в
`.opencode/tasks/WORK_QUEUE.md` и помечает готовые к выполнению карточки
`Статус: READY`.

Карточки выполняются сверху вниз, по одной, с отдельным evidence и commit (если
разрешён) для каждой. Зависимые карточки остаются `DRAFT` или `BLOCKED` до
приёмки предыдущей; независимые можно пометить `READY` одновременно. Пока
READY-задач нет, executor не имеет права менять код, запускать эксперименты или
создавать commit.

### 2. Исполнение в OpenCode

В сессии OpenCode, открытой для корня репозитория, дайте исполнителю короткую
команду:

```text
Выполни все READY-задачи в очереди сверху вниз. В конце верни отдельное evidence по каждой задаче.
```

Executor может менять только пути, перечисленные в конкретной task card. Он обязан
прогнать указанные в ней проверки. Стандартный полный прогон уже разрешён без
дополнительного подтверждения:

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -q
```

Остальные shell-команды запрашивают подтверждение. Сеть, доступ вне рабочего
каталога, изменение конфигурации OpenCode, policies и deploy запрещены. Агент не
может читать `.env`, запускать subagent, делать `push`, создавать PR, а также
использовать `git reset`, `git restore` или `git clean`.

Если task card содержит `Commit: ALLOWED`, executor может создать один локальный
commit для неё после проверок. Он обязан проверить `git status`, не затронуть
предсуществующие изменения и вернуть hash commit. При неоднозначной границе commit
не создаётся.

### 2.1. testdev, Docker и Agent00X-sandbox

Эти среды не включаются по умолчанию. В очереди для такой задачи обязательно
заполняются `Среда исполнения`, `Внешняя цель` и `Разрешённые внешние команды`.
Команды к `testdev` или Git remote всё равно появятся в приложении как запрос на
подтверждение; разрешайте только точное действие из task card.

`testdev` сейчас используется для preflight GitHub App. Этот сервис проверяет
metadata при boot и не является разрешением на получение token или публикацию.
`Agent00X-sandbox` — отдельный allowlisted репозиторий исторических spike PR, не
текущий `origin` проекта и не доказательство сквозной безопасности. Executor не
может пушить туда, создавать PR, читать `.env.github-app` или менять systemd
сервисы. Docker integration test запускается только когда task card явно содержит
`RUN_DOCKER_SANDBOX_TESTS=1`, образ и ожидаемый результат.

### 3. Локальная проверка и доработка замечаний

После результата executor Codex проводит независимое ревью. Если найдена
конкретная проблема, Codex переводит карточку в `REVIEW` и записывает
`CHANGES REQUESTED` с воспроизводимым дефектом. В новой сессии OpenCode выберите
агента `reviewer-remediator` и передайте только такую команду:

```text
Проверь и доработай REVIEW-карточки с CHANGES REQUESTED сверху вниз. Не принимай и не закрывай их; верни evidence для Control Plane.
```

Этот агент не может менять очередь или правила. Он независим от первого executor,
но имеет тот же ограниченный доступ к коду и может создать отдельный локальный
remediation commit. Если проблема не подтверждается или scope недостаточен, он
останавливается с `BLOCKED`, а не расширяет задачу.

### 4. Финальное ревью и публикация — вне OpenCode

После evidence reviewer-remediator Codex заново проводит независимое ревью против
plan и task card. Только после отдельного решения пользователя Codex может
выполнить `git push` в GitHub. Ни один OpenCode-агент такой возможности не получает.

## Формат очереди

Шаблон находится в [WORK_QUEUE.md](tasks/WORK_QUEUE.md). Каждая карточка должна
содержать ID, статус, цель, гипотезу, зависимости, разрешённые пути, критерии
приёмки, тесты, условие commit и риски. Это позволяет передать агенту несколько
изолированных экспериментов без предоставления свободы менять scope.

## Как меняются правила и доступы

Их меняет только Codex:

- общие ограничения и командные разрешения — `../opencode.json`;
- общие инструкции — `../AGENTS.md`;
- возможности исполнителя — `agents/executor.md`;
- задачи и их статусы — `tasks/WORK_QUEUE.md`.

После правки `AGENTS.md` начните новую сессию OpenCode: уже загруженные инструкции
могут сохраняться в контексте старой сессии. Конфигурация ограничивает инструменты,
но не заменяет настоящий sandbox; для полностью недоверенного исполнителя используйте
отдельный пользовательский аккаунт, изолированный checkout или контейнер без
секретов и авторизованных Git credentials.

## Контрольный список передачи результата

- Plan превращён в одну или несколько READY task cards; scope не расширен.
- В diff нет секретов, credentials, временных файлов или незаявленных правок.
- Есть точные команды тестов и их результаты.
- Codex провёл ревью и отметил непройденные проверки.
- Executor может создать только локальный commit. Push, PR и публикацию в GitHub
  выполняет только Codex после решения пользователя.
