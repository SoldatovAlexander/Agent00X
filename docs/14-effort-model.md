# Модель относительных затрат

Статус: принято  
Версия: 0.1

## Решение

Платформа использует `Effort Units` — относительные единицы затрат. Денежная
цена не является обязательной частью ядра: её можно добавить позднее через
адаптер конкретного провайдера или инфраструктуры.

Это позволяет одинаково учитывать облачные и локальные модели, использование
GPU/CPU, внешние инструменты, sandbox и работу субагентов.

## Базовая шкала

Сильная модель, выбранная организацией как референсная, получает значение `100`.
Остальные ресурсы задаются относительно неё и калибруются на реальных задачах.

| Tier | Ориентир Effort Units | Примеры работы |
|---|---:|---|
| `local_light` | 1–5 | извлечение, классификация, форматирование |
| `cheap` | 5–15 | типовые подзадачи и поиск |
| `medium` | 20–40 | реализация по ясной спецификации |
| `strong` | 100 | архитектура, диагностика, арбитраж |
| `strong_verified` | 130–180 | сильная модель и независимая проверка |

Значения не являются тарифом или обещанием точной стоимости. Это стартовые
коэффициенты для выбора между альтернативами и они пересматриваются по данным
валидации.

## Effort Profile процесса

```yaml
effort_profile:
  budget_units: 240
  reference_model: strong-model-v1
  reference_unit: 100
  reserve_for_verification: 60
  max_subagent_units: 50
  max_parallel_agents: 3
  allowed_tiers: [local_light, cheap, medium, strong]
  strong_model_limit: 2
  stop_when_remaining_below: 10
```

Субагент получает подбюджет из остатка родителя. Factory отказывает в создании
новой ветви, если требуемый резерв для verification или безопасного завершения
процесса будет исчерпан.

## Фактический trace

Если измерить денежную цену невозможно или не требуется, run фиксирует только
относительную оценку и наблюдаемое потребление:

```yaml
effort_record:
  estimated_units: 35
  observed_units: 42
  model_tier: medium
  reference_ratio: 0.42
  tool_units: 3
  compute_units: 2
  budget_remaining_units: 198
  calibration_version: 2026-09-04.1
```

`observed_units` могут быть вычислены из токенов, latency, GPU-time, числа
вызовов и расхода инструментов, но конкретная формула является сменной и
версионируется.

## Decision rule

Создание субагента, эскалация на сильную модель или запуск дополнительной
проверки рассматриваются как инвестиции:

```text
использовать вариант, если ожидаемая польза
превышает effort + риск + задержку + координационную сложность
```

Критический риск не компенсируется низкими effort units: политика безопасности
всегда имеет приоритет над оптимизацией затрат.

## Денежный адаптер

Когда доступны точные данные провайдера, адаптер сопоставляет Effort Units с
валютой, но не изменяет базовые контракты:

```text
Effort Units -> provider-specific price -> currency report
```

Денежный отчёт остаётся наблюдаемым свойством запуска, а не условием его
корректности.
